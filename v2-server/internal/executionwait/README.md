# 执行结果读取与结算重试

本包只重试读取和已决定结果的落库，不重新派发 prompt，也不停止执行。

- `Policy.Read` 默认最多等待一分钟，每 250ms 重试一次；每次查询最多五秒，且不能超过剩余预算。
  只重试公共执行端的 `ErrUnavailable` 和查询超时；资源不可见、游标非法等确定拒绝立即返回。
  上限针对一次持续的读失败或尚未补写的结果，不限制正常 Agent 轮次的运行时长。
- `stream.Next` 把事件、会话与结束后的事件复查放在同一个读预算内；完整读取成功才前移 cursor。
  健康的空轮询重新开始预算。停止订阅或取消请求立即退出，不取消执行。
- 工作流和任务运行在订阅失败或流中断时，继续轮询持久化的原轮次结果；读取恢复但结果尚未补写时继续等待。
  流内部的一分钟耗尽后，调用方另有一分钟读取原结果。因此两级连续失败最多等待两分钟，再决定调用方失败。
- 读预算耗尽后，工作流使用可恢复的 session 失败，用户可以恢复运行；任务记录
  `execution_result_unavailable` 并进入待验收，用户可以重新运行。新任务运行按既有路径先结束旧会话。
  调用方的读取失败不改写执行服务已保存或稍后补写的真实结果。
- `Policy.Store` 保留已决定的业务结算并重试临时 PostgreSQL/网络错误，数据库恢复后补写；不会重新读取并改变已决定的失败。
  这里没有读取预算：每次写入仍限五秒，循环由所属 host 的关闭 context 取消并等待退出。确定的数据错误不重试。
  进程退出前尚未落库的按既有启动中断恢复处理。

工作流补记完成后显式续跑调度，覆盖节点已提交但后继调度读取失败的情况；交互式节点回合后的挂起（`park`）同样重试临时存储错误，并在提交结果不明时通过 `pending -> pending` 刷新确认。任务补记分别保留轮次结算与任务状态移动的进度，
连接丢失导致提交结果不明时核对原轮次；不会用旧轮次的结果移动新轮次的任务。

`retry_test.go` 与两个调用方的 `result_retry_test.go` 使用虚拟时间验证有界等待、补写、取消、失败结算和提交结果不明。
`executionruntime/outage_test.go` 使用真实 PostgreSQL，关闭已有连接并拒绝新连接，让读取和终态写入同时失败，恢复后验证三种观察者的最终结果。
该集成测试需要 `TEST_DATABASE_URL`；未配置时跳过，不代表数据库中断场景已经验收。
