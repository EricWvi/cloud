# 单机离线部署

[English](deployment.en.md)

依据：[Cloud 单进程（A1）](https://github.com/ora-space/specs/blob/main/decisions/cloud/lifecycle/0-single-process-cloud-on-enterprise-intranet.md) D2/D5/D6 和[登录与会话（A6）](https://github.com/ora-space/specs/blob/main/decisions/cloud/login/0-idaas-or-email-login-with-shared-web-and-desktop-sessions.md)。
当前构建不提供 IDaaS 登录，`V2_LOGIN=idaas` 在访问数据前拒绝启动，不能作为可用部署上线，
不得回落到 email。数据库迁移在启动时自动执行。正式部署须使用支持所需能力的版本，
并配置经过验证的 HTTPS 入口。

## 在外网构建

在与目标机同架构的 Linux 上，安装 Go（版本见 go.mod）、Node >=24、npm、Python 3、Git、curl、
Rust 1.95.0 和已信任来源的 Deno 2.9.5。设置 `DESKTOP_REPOSITORY` 指向包含 prepare-node.sh
固定提交的 desktop 仓库。执行：

```sh
DESKTOP_REPOSITORY=/build/desktop V2_NODE_ASSETS_DIR=/build/assets \
  V2_OFFLINE_OUTPUT=/build/cloud-linux.tar.gz task v2:offline:build
```

入口先调用 `prepare-node.sh`：按固定提交编译 Node/reaper，按固定 SHA-256 校验两个 Agent
插件，检查 Deno 版本并记录本机摘要。构建并发限制为 2。Deno 和本机编译摘要只证明完整性，
不是官方发布签名；构建机及其工具链必须可信。前端强制 `VITE_DEMO_MOCK=0`，使用 offline mode；
构建后扫描前端产物，发现录屏用的演示 mock 就中止打包（`npm run demo:check`）。
包只包含服务端、web 构建、五项运行资源、清单、启动器和本文档，不复制用户配置、数据库或数据目录。
准备目录中的其他内容（包括源码、用户文件）不进入包。`assets.json` 使用相对路径，运行时仍兼容旧的绝对路径开发清单。

将包通过受信任通道传入内网，解压到新的版本目录，在该目录执行 `sha256sum --check SHA256SUMS`。
这份清单检测传输损坏，不代替可信传输或发布签名。解压及启动不下载资源；运行时仍需访问配置的
PostgreSQL、IDaaS、模型和内部 Git/S3 服务。Git 和系统库须预先安装，离线包不包括操作系统依赖。

## 主机与配置

使用专用非 root 系统账号运行 Cloud。第一版 Agent 与 Cloud 同用户、不隔离，仅适用于互相信任的成员。
准备 PostgreSQL 和专用数据库、数据库身份；不要使用演示数据库或演示凭据。启动时自动执行尚未应用的
版本化迁移，数据库身份需要在该库中建表的权限。由引入迁移之前的版本创建的数据库不能升级，启动会拒绝；
须删除并重建该库。

在进程管理器的受保护配置中设置以下变量，不将密钥写入包或命令日志：

- `V2_LOGIN=idaas`：唯一部署登录方式；当前构建不提供此能力，启动会明确拒绝。
  `/auth/providers` 不含 `email` 时，前端按部署模式处理，只隐藏只写浏览器的「模型连接」页；角色目录由服务端提供，设置页「角色」与工作流角色字段照常显示。
- `V2_PUBLIC_URL`：部署公开 HTTPS 地址，只写根地址、不带路径（见「HTTPS 入口」）；
  `V2_IDAAS_BASE_URL`、`V2_IDAAS_CLIENT_ID`、`V2_IDAAS_CLIENT_SECRET` 是 A6 规定的部署配置；
  当前构建尚不支持 IDaaS 登录。
- `V2_DATABASE_URL`：专用 PostgreSQL 连接，按企业要求启用 TLS 和最小权限。
- `V2_ADDR`：明文 HTTP 监听地址，默认 `127.0.0.1:8090`。只允许企业 HTTPS 入口连接，绑定方式见「HTTPS 入口」；
  v2-server 自身不终止 TLS。部署必须使用 HTTPS，不得将这里的 HTTP 监听直接当作正式用户入口。
- `V2_DATA_DIR`：绝对、持久化目录，例如 `/srv/ora/data`；目录和所有父目录均不可被组或其他人写入，
  不能放 `/tmp`。由运行账号创建，建议 `0700`，不要通过宽化权限解决 Node 启动失败。
- `V2_MARKET_CREDENTIAL_KEY`：按 pluginmarket 与 projectrepos 要求的密钥格式生成（32 字节 Base64）；
  作为稳定密钥持久保存，与数据一起备份。重建、替换或丢失会使现有市场 S3 AK/SK、自定义市场 Git 凭据、租户 MCP 设置以及私有项目仓库令牌无法解密。
- `V2_PLUGIN_MARKETPLACE_URL`：启动器未配置时设为空，关闭官方市场。直接启动 binary 时未设置仍使用开发默认；
  显式空字符串关闭同步和旧官方目录可见性。自定义空间市场支持 S3+AKSK 及管理员在设置页配置的内部 HTTPS Git 认证
  （用户名与令牌/密码，经 `V2_MARKET_CREDENTIAL_KEY` 加密存库）；Git 同步禁用重定向（`http.followRedirects=false`），
  须填写仓库当前准确地址，更改仓库地址时需同时填写新凭据或显式清除旧凭据。
- `V2_PLUGIN_MARKETPLACE_BRANCH`、`V2_PLUGIN_MARKETPLACE_INTERVAL`：仅官方源启用时使用，默认 main、5m。
- `V2_MODEL_*` / `V2_ANTHROPIC_MODEL_*`：模型连接，具体变量见服务 README。
  改变连接、模型或凭据绑定可能让旧对话不能继续；在变更前通知用户，保留历史并新建对话。

`start.sh` 从自身位置确定 `V2_FRONTEND_DIR` 和 `V2_NODE_ASSETS_DIR`，校验包文件后执行服务。
不能传入 `-fixture-check`、`-test-fixtures`、`-cleanup` 作为部署启动方式。程序不会加载开发用户 preset、
准备 demo 项目或预热 demo Node；当前构建因不提供 IDaaS 登录而直接阻止部署启动。

企业 CA 必须安装到运行主机的系统信任库（按企业发行版流程更新信任库），Git 和 Go HTTPS 均使用
系统 CA。不得关闭 TLS 校验。

## HTTPS 入口

HTTPS 由企业现有的入口（网关或反向代理）终止。v2-server 不配置 TLS，离线包也不带反向代理：
IDaaS 回调域名和证书本来就归企业入口管理。v2-server 在 `V2_ADDR` 上只提供明文 HTTP，
不读取 `X-Forwarded-*` 等转发头。提供 IDaaS 登录的目标版本只从 `V2_PUBLIC_URL` 得到公开地址，
在它为 https 时给会话 Cookie 加 `Secure` 和 `__Host-` 前缀，并只接受来自该地址的带会话写请求；
当前构建尚不具备这些行为。

入口必须满足：

- 不改写路径：浏览器请求的路径原样到达 v2-server，不加也不去掉路径前缀。页面、`/api` 和 `/auth`
  都挂在根路径，前端请求也用 `/` 开头的绝对路径，所以公开地址只能是根地址
  （例如 `https://ora.example.com`），不能放在路径前缀下。v2-server 不读取 `Host`，入口改写 `Host`
  不影响它。目标版本按 `Origin` 判断带会话的写请求，入口不得改写 `Origin`。
- 不改写 `Set-Cookie`（不加 `Domain`，不改 `Path`）：目标版本的 `__Host-` Cookie 一旦被加上 `Domain`
  或改了 `Path`，浏览器就会拒收，登录保持不住。
- 只转发到一个 v2-server 进程，不在多个实例间做负载均衡：v2-server 是单进程服务，目标版本把进行中的
  登录保存在进程内存里。
- 不缓冲 `text/event-stream` 响应。对话、任务执行、工作流运行和工作流节点的实时更新都走 SSE，
  路径分别以 `/chat/conversations/{cid}/events`、`/tasks/{taskid}/runs/{rid}/events`、
  `/workflow-runs/{rid}/events` 和 `/workflow-runs/{rid}/nodes/{nodeRunId}/events` 结尾
  （均在 `/api/v2/tenants/{tid}` 下）。v2-server 已返回 `Cache-Control: no-cache` 和
  `X-Accel-Buffering: no`；入口若不认这两个头，须对这些路径显式关闭缓冲，否则更新会在结束时一次性出现。
- 对浏览器启用 HTTP/2。每个打开的对话、任务执行和工作流运行页面都占一条长连接；HTTP/1.1 下浏览器
  对同一地址最多开 6 条连接，同时打开几个页面后，其余请求会排队，页面卡住。
- 不限制这些 SSE 连接的总时长，或把上限设得足够长。页面打开期间 SSE 连接一直保持：对话的连接跨多轮，
  直到对话会话结束；工作流运行页的连接直到离开页面才断开，与单次模型请求的时长无关。v2-server
  每 15 秒发一次心跳，入口的空闲超时须明显长于 15 秒（建议不少于 60 秒）。模型请求由 v2-server
  直接发往模型服务，不经过入口，`V2_MODEL_IDLE_TIMEOUT`、`V2_MODEL_MAX_DURATION` 与入口超时无关。
  入口切断 SSE 连接不会停止执行：浏览器几秒后自动重连，对话、任务执行和工作流节点的事件按
  `Last-Event-ID` 从断点续传，工作流运行页重新读取运行状态，页面只是短暂停顿。但如果重连时入口
  返回错误（例如 v2-server 重启期间的 502），浏览器不再重连，页面停止实时更新，刷新后恢复；
  重启后请让用户刷新已打开的页面。
- 请求体上限不小于 v2-server 自身的上限。最大的是 6 MiB，用于工作流定义、草稿和版本，以及启动运行、
  填写表单、节点追问等工作流运行请求；技能和角色的创建、更新与导入为 2 MiB，其余接口更小。
  入口不得另外截断请求体，否则保存大的工作流或启动运行会在入口失败。
- IDaaS 回调：目标版本把回调地址固定为 `<V2_PUBLIC_URL>/auth/callback/huawei-idaas`，只由
  `V2_PUBLIC_URL` 得出，启动日志会打印；入口须把这个路径连同查询串原样转发。当前构建还没有这条路由。

入口到 `V2_ADDR` 这一跳是未加密的 HTTP，使用 HTTP/1.1；v2-server 不支持明文 HTTP/2（h2c）。
入口与 v2-server 在同一主机时，`V2_ADDR` 绑定 `127.0.0.1:<端口>`；不在同一主机时，绑定内网地址，
并用主机防火墙只允许入口所在地址连接该端口，避免其他机器绕过 HTTPS 直接访问。

## 向现场确认的入口信息

部署前向企业网络或网关负责人确认并记录：

- 入口类型和版本（网关产品或反向代理）；
- 公开域名，即 `V2_PUBLIC_URL`；
- 证书签发方，是否为企业 CA，以及运行主机和员工浏览器是否已信任该 CA；
- 是否对浏览器启用 HTTP/2；
- 能否对上述 SSE 路径关闭缓冲、把空闲超时设到 60 秒以上、取消或放宽总时长上限；
- 请求体上限及能否调整；
- 是否改写路径、`Origin` 或 `Set-Cookie`，能否关闭；
- 是否只转发到一个 v2-server 实例；
- 入口相对 v2-server 主机的位置：同一主机，或另一台主机及其内网地址（用于配置防火墙）。

## 首次内网验收

仅对已提供 IDaaS 登录的目标版本执行以下完整验收，并遵循该版本的管理员初始化说明；
本构建仅供部署预检，不能上线，也不能以邮箱登录或模型 fixture 替代现场验收。

1. 准备专用 PostgreSQL、持久数据卷、已登记的 IDaaS 应用、管理员和第二名员工账号，以及一个真实项目、
   可用模型连接、含可安装工作流插件的内部 Git 仓库和对应 S3 包。确认包与目标 Linux 架构匹配，执行
   `sha256sum --check SHA256SUMS` 全部通过。为验收使用独立实例，不重启或修改其他实例。
2. 按主机发行版的企业流程将企业 CA 安装到系统信任库。以实际 Cloud 运行身份，使用现场已有的 DNS/TLS
   诊断工具，逐一核对 Git、S3 和模型主机：解析结果符合预期，HTTPS 主机名、证书链和有效期校验通过，
   再经 Cloud 执行下述实际请求。不得关闭证书校验或公网地址检查；若内网解析地址被现有地址策略拒绝，
   记录为阻断条件，不以 TLS 绕过或放宽地址检查继续。凭据只通过受保护的配置或设置页输入，
   不放入命令行、URL、截图或日志。
3. 记录「向现场确认的入口信息」，按「HTTPS 入口」配置入口和 `V2_ADDR`。在入口所在主机执行
   `curl -sS -m 5 http://<V2_ADDR>/healthz`，应返回含 `"status":"ok"` 的 JSON；在另一台内网机器执行
   同一命令，应超时或连接被拒。入口与 v2-server 同机时，`ss -ltn` 中该端口只显示 `127.0.0.1:<端口>`。
4. 在验收实例按目标版本说明完成迁移和 IDaaS 管理员初始化，再邀请第二名员工登录并加入团队。
   从浏览器经入口访问 `V2_PUBLIC_URL`，确认 web 与 `/api` 同源，开发者工具「网络」面板的协议列显示 `h2`，
   IDaaS 回调跳回登记的公开 HTTPS 地址，会话 Cookie 名带 `__Host-` 前缀，并带 `Secure`、`HttpOnly` 和
   `SameSite=Lax`；核对不存在预置演示账号、项目或内容。
5. 管理员在“设置 → 插件 → 管理市场”添加自定义内部 HTTPS Git 来源，填写当前准确仓库 URL（无重定向）、
   分支、Git 用户名和只读令牌，包下载选择 S3 签名下载，分别填写 S3 端点、桶、区域及 AK/SK。Git 凭据与 S3 凭据分开，
   持久保存并备份 `V2_MARKET_CREDENTIAL_KEY`。点击同步，确认来源无失败提示、目录出现预期版本；
   安装一个工作流插件，确认工作流已导入并可在工作流页打开。
6. 另建独立验收来源（使用不同仓库地址，不能只改同一仓库 URL 写法），先正确同步得到目录，
   再仅替换该来源的 Git 令牌为错误值并同步，确认内部 Git 服务器的认证失败输出被准确识别为可读的仓库认证失败提示
   （而不是笼统的网络/克隆失败）且上一版目录保留。
   再清除已保存的 Git 认证并同步：需要认证的仓库仍应明确失败，旧目录仍保留。恢复正确凭据后应可再次同步。
   全程不修改正常来源；Git 失败时不要更换 S3 密钥来掩盖问题。
7. 在真实项目上运行已安装的工作流并完成一轮对话，确认实际模型、包下载和 Node 执行均成功，结果与历史可读。
   经入口观察时，对话和工作流的输出须边生成边出现，而不是结束时一次性出现。再打开一个对话页，
   在浏览器开发者工具的「网络」面板按 `events` 过滤，保持页面打开，时长超过第 3 步记录的入口空闲超时
   和总时长上限（取较大者再加几分钟）。通过条件：该对话的 `events` 请求始终只有一条，且仍处于打开状态；
   如果入口的总时长上限无法取消，到时出现的新 `events` 请求须带 `Last-Event-ID` 请求头、状态为 200，
   页面内容不缺也不重复。记录成员、插件、历史和数据卷中的验收文件，然后只重启验收实例；
   确认登录后这些状态与文件仍在、密钥仍可解密来源凭据且可再次同步。
   重启前未结束的执行应标记中断，不以自动续跑作为成功标准。

每步保存脱敏证据：程序版本、平台架构、SHA 校验结果、时间、操作和结果；不记录密钥、令牌或完整认证响应。
失败时按顺序区分 DNS 解析、TLS 信任/主机名、Git 或 S3/模型认证、包下载/摘要校验、Node/工作流执行链，
记录安全错误码与脱敏提示后停止对应步骤；不得把目录保留或 fixture 输出当作同步、安装或真实执行成功。

## 备份和升级

备份 PostgreSQL、整个 `V2_DATA_DIR` 数据卷和稳定的加密密钥；采用停机或一致性快照确保数据库与数据卷一致，
验证能恢复。Agent 改动只在本机工作目录，不会自动推送到 Git，不能只备份数据库。

升级前停止本实例并确认 Node 已退出，备份后将新包解压到新的程序目录，校验摘要。新版本启动时自动执行迁移，
因此升级前必须先备份；迁移失败时启动报错并停在上一个已完成的迁移，错误信息会列出本次启动已应用的迁移。由引入迁移之前的版本创建的数据库
须删除并重建，启动会拒绝。数据库记录比程序更新的迁移、或已应用的迁移内容被改动时，启动同样拒绝。
替换程序和资源，保持数据目录、数据库、密钥及主机配置不变；不要删除数据、运行 demo reset、重新 seed 或复制旧包覆盖
新版本文件。未完成的执行在重启后标记中断，不自动续跑。数据库迁移后的回退必须按已验证的备份恢复方案进行，
不能假设替换旧 binary 即可回退。静态 HTML 和资源使用 `no-cache`，让浏览器在升级后重新验证文件。
